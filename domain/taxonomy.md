# Taxonomy

用于沉淀整个 vault 共用的业务分类。通用 `Domain` 只解决项目知识分面；这里可以定义团队自己的行业分类、会议类型、决定类型和工作流类型。

## 默认 Domain

| Domain | 用途 |
| --- | --- |
| `业务目标` | 项目为什么做、服务谁、成功标准、客户或内部目标。 |
| `范围/需求` | 做什么、不做什么、需求变化、边界确认、优先级。 |
| `方案/决策` | 已定方案、关键取舍、替代旧结论、方案路线。 |
| `数据/证据` | 数据来源、指标、材料、事实依据、调研结论、附件证据。 |
| `交付/执行` | 里程碑、排期、验收、培训、上线、执行进展。 |
| `风险/依赖` | 阻塞、不确定性、外部依赖、风险和待确认前提。 |
| `协作/责任` | owner、分工、会议节奏、客户沟通、跨团队协作。 |

## 会议类型

| Meeting Type | 用途 | 典型产出 |
| --- | --- | --- |
| `discovery` | 需求探索、背景理解、问题澄清。 | open question、范围假设、后续调研 todo。 |
| `decision` | 确认方向、范围、资源、报价或方案。 | decision、supersedes、owner。 |
| `delivery-sync` | 项目执行同步。 | todo、风险、依赖、timeline 更新。 |
| `review` | 方案、材料、交付物或结果评审。 | 修改意见、通过/不通过、缺口。 |
| `retrospective` | 复盘。 | lesson、改进项、后续机制。 |

## 决定类型

| Decision Type | 用途 |
| --- | --- |
| `scope` | 范围、边界、不做什么。 |
| `priority` | 优先级和阶段安排。 |
| `solution` | 方案路线和技术/业务取舍。 |
| `commercial` | 报价、采购、合同、商务口径。 |
| `delivery` | 排期、里程碑、验收。 |
| `governance` | 权限、流程、质量、安全、协作机制。 |

## 项目自定义分类

如果某个项目需要行业分类，在项目级 `knowledge/project-taxonomy.md` 中覆盖或扩展，不要直接改全局 taxonomy，除非多个项目都会复用。
